## 🤖 วิธีที่ Claude ต้องจัด (อ่านก่อนลงมือ)

### ขั้นที่ 1 — ถามให้ครบก่อนกระจาย

อย่าเดาแทน pete ถ้าสเปคยังกำกวม ให้ถามก่อน โดยเฉพาะ:

- มันอยู่ layer ไหน (หรือเป็น layer ใหม่)
- ต้องมีตาราง/คอลัมน์ใหม่ไหม
- ใครเห็นข้อมูลนี้ได้บ้าง (→ กำหนด RLS)
- ชื่อหน้า/component ใน FlutterFlow ชื่ออะไรจริง ๆ

### ขั้นที่ 2 — 🔴 เช็คผลกระทบข้าม layer ก่อนเสมอ

ก่อนเขียนลง layer ไฟล์ ต้องถามตัวเองว่า **ของใหม่นี้กระทบ layer อื่นไหม**

บทเรียนจาก D-01: การแก้ `public_profiles` ครั้งเดียวกระทบ L1/L2/L4 พร้อมกัน ตอนนั้นเกือบพลาดเพราะคิดว่าเป็นปัญหาเฉพาะ Layer 2

เช็คลิสต์:

- [ ] ต้องดึงชื่อ/รูปผู้ใช้ไหม → ต้องใช้ **PT-01** (`public_profiles`)
- [ ] แตะตาราง `products` ไหม → กระทบทั้ง L2 (moderation) และ L5 (status)
- [ ] แตะ chat ไหม → กระทบ L4 + ปุ่มแชทใน L2/L3 (**PT-02**)
- [ ] มีการแจ้งเตือนไหม → เกี่ยวกับ L6
- [ ] pattern นี้จะถูกใช้ซ้ำ ≥ 2 layer ไหม → เขียนเป็น **PT-xx** ใน `PATTERNS.md` แทนที่จะเล่าซ้ำในแต่ละ layer

### ขั้นที่ 3 — กระจายตามตารางนี้

| ประเภทของที่เขียนมา | ปลายทาง | รูปแบบ |
|---|---|---|
| สเปคหน้าจอ / Action Flow / ขั้นตอนทำงาน | `layers/Lx-*.md` | ต่อในหัวข้อ 🎨 หรือ 🧩 ของ layer นั้น |
| SQL / ตาราง / RPC ที่ยังไม่รัน | `PROPOSED_SQL.md` | เพิ่มเป็น P-xx ใหม่ + เพิ่มแถวในตารางสรุปหัวไฟล์ |
| schema ที่ apply ลง Supabase แล้ว | `SCHEMA.md` | อัปเดตตาราง/RLS/Realtime ให้ตรง |
| ขั้นตอนที่ใช้ซ้ำ ≥ 2 layer | `PATTERNS.md` | เพิ่มเป็น PT-xx ใหม่ แล้วให้ layer อ้างรหัสแทนเล่าซ้ำ |
| "ตัดสินใจแล้วว่าจะ..." / "เปลี่ยนใจจาก...เป็น..." | `DECISIONS.md` | เพิ่มเป็น D-xx ใหม่ (append เท่านั้น ห้ามลบของเก่า) |
| งานที่ต้องทำ / คำถามที่ยังไม่ตัดสินใจ | `STATUS.md` | ใส่ในหัวข้อ "คิวถัดไป" หรือ "คำถามที่ยังไม่ตัดสินใจ" |
| เงื่อนไขที่ต้องผ่านถึงจะเรียกว่าเสร็จ | `layers/Lx` (🧪 DoD) + `checks/Lx.sql` | DoD เป็นข้อความ / checks เป็น query ที่รันแล้วรู้ผลทันที |

### ขั้นที่ 4 — เสร็จแล้ว

- ลบรายการที่จัดแล้วออกจาก INBOX (อย่าปล่อยค้างไว้ ไฟล์นี้ต้องว่างเป็นปกติ)
- สรุปให้ pete ว่าอะไรไปไฟล์ไหน + ชี้ว่ามีผลกระทบข้าม layer ตรงไหนบ้าง
- ถ้ามีสเปคใหม่ที่ทำให้ DoD เดิมไม่พอ → เพิ่ม query ใน `checks/Lx.sql` ด้วย

### ❌ ห้ามทำ

- ห้ามคัดลอก schema จาก `SCHEMA.md` มาวางซ้ำในไฟล์ layer
- ห้ามเขียน SQL ลงไฟล์ layer โดยตรง (ให้อยู่ที่ `SCHEMA.md` หรือ `PROPOSED_SQL.md` เท่านั้น แล้วอ้างรหัส)
- ห้ามเขียนสเปคใหม่ทับของเดิมโดยไม่บอก — ถ้าสิ่งที่ pete เขียนมาขัดกับที่ตกลงไว้แล้ว ให้ **ถามก่อน** แล้วบันทึกเป็น D-xx ใหม่
